# Capability Registry

The registry is the machine-readable control surface for the 120 capability units.

## Current principle

The 120 existing units are not reconstructed here. They are progressively connected to this registry as their identity, source, evidence and consumption path become operationally known.

## Lifecycle

IDENTIFIED → CONTRACTED → VERIFIED → CONSUMABLE → REUSED → COMPOSED

## Required evidence

A promoted entry should point to concrete evidence wherever available:

- source repository/path
- contract
- consumer
- commit SHA
- workflow/run ID
- artifact or evidence path
- result
- adaptation notes

## First pattern

TRACE+VERIFY is the first proven reuse pattern and is recorded in the registry as a pattern, not as an invented CAP number.
